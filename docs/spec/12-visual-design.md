# 12 — Visual Design Direction

> **Approved direction (OD-04, ADR-0007):** the Photoshop/Illustrator-designed enthusiast and personal web of about 2003–2009, built with modern CSS, responsive layout, accessibility and frontend engineering. **This is not a "retro pixel portfolio."**

## 1. Concept: "Designed, not generated: a 2000s enthusiast site with modern engineering"

Imagine a designer from the mid-2000s personal/fansite scene who has CSS Grid, container queries, variable fonts, SVG, high-DPI screens, WCAG and a performance budget. The site should feel **intentionally made by hand**: layered, textured, editorial and dense, while being fast, accessible and responsive.

### The actual reference (what defines the look)

- **Photoshop/Illustrator-era graphic design:** layered masthead compositions, textured interface chrome (subtle noise, fine stripes, halftone, brushed or paper surfaces), crafted gradients *used as material* (bevels, gel buttons, specular highlights) rather than background blobs, drop shadows with intent, custom-drawn dividers and ornaments, and section header graphics.
- **Portal and fansite information architecture:** a multi-column layout, boxed modules with title bars, tabbed navigation, sidebars with "latest updates", link lists and affiliates-style link buttons, and dense but ordered pages. The circa-2008 NarutoProject is one example.
- **Japanese/anime community sites (個人サイト culture):** 更新履歴 (update logs), menu structures, banners, careful typographic hierarchy that mixes Latin and Japanese.
- **Editorial layouts:** magazine-style case studies, pull quotes, captions, sidebars and footnotes.
- **Badges and buttons:** 88×31 buttons, "valid" style badges (real ones, generated by CI), and web buttons.

### Accents only

Pixel art and 8-bit or bitmap elements MAY appear as **accents**: small icons, a 404 sprite, the occasional badge, a pixel label in chrome. They MUST NOT define the overall visual language, typography or layout.

## 2. Explicit anti-patterns

- **The generic modern portfolio:** SaaS hero with gradient blobs · bento grid · floating tech logos · generic AI illustrations · glassmorphism everywhere · "Hi, I'm X 👋" · skill progress bars · tech-logo clouds · a card grid as the only layout primitive.
- **The generic retro portfolio:** a whole site in pixel fonts · CRT/scanline filters everywhere · faux Windows 95 windows as the main UI · 8-bit palette as the identity · "retro" as a costume rather than as design craft.
- **The genuinely broken 2000s web:** fixed 800 px layouts · text in images · table layouts · tiny low-contrast text · auto-playing media · splash or intro gates · marquee/blink without reduced-motion handling · low-resolution JPEG artefacts.

## 3. Layout system

- **Portal grid** from CSS Grid with named areas: `masthead / nav / main / sidebar / footer`.
  - ≥ 1100 px: 3 columns (nav rail ~180 px · main fluid, max 72ch for prose · sidebar ~260 px).
  - 700–1099 px: 2 columns (main + sidebar). Nav becomes tabs under the masthead.
  - < 700 px: 1 column. Sidebar modules flow after the main content, except quick facts, which moves up on the home page.
- **Modules** (`.box`): a title bar (a graphic header strip with live-text label), crafted chrome (layered `box-shadow`s, `border-image` from SVG, subtle texture), and a content area. Components use container queries, so a module renders correctly in any column.
- **Masthead:** a layered composition (SVG plus CSS, optionally with provided or photographic assets) that reflows across breakpoints. Art direction uses `<picture>`/container queries, not a single squashed bitmap.
- **Density:** tighter than modern norms in chrome and sidebars. Prose keeps a generous measure and leading.

## 4. One design system, related section identities

| | **Portal** (base system) | **Archive** (`/timeline`) | **Dictionary** (`/kanji`) |
|---|---|---|---|
| Mood | Mid-2000s enthusiast portal: composed masthead, deep ink chrome, one warm accent, light content panels, textured surfaces | Newspaper morgue and scrapbook: column rules, halftone, clipping edges, typewriter captions, archive labels | Dictionary and 原稿用紙: paper surfaces, 朱 vermilion, 墨 sumi black, grid lines, 判子-style marks for verified achievements |
| Chrome | Bevelled and glossy module headers, tabs, link buttons, badges | Rules, drop caps, `clip-path` clipping edges | Hairline grids, stamps, ruby-friendly spacing |

The identities share the grid, components, tokens architecture, type scale and interaction patterns. A section identity may override only **tokens and a small set of decorative components** (`data-identity="archive|dictionary"` on `<body>`).

## 5. Design tokens (`src/styles/tokens.css`)

- Colour: `--ink`, `--paper`, `--chrome-{1..4}`, `--accent`, `--accent-ink`, `--link`, `--visited` (visited links get a colour, as in the era), `--focus`, `--ok/--warn`, plus texture tokens (`--texture-noise`, `--texture-stripe`). Each is defined for light and dark ("night mode") and per identity. A token-contrast unit test enforces A11Y-04.
- Type: modular scale with fluid `clamp()` sizes. Space: a 4 px baseline scale.
- Material: `--bevel-light`, `--bevel-dark`, `--gloss`, `--inset-shadow`, `--radius-chrome` (small; 2000s chrome was rarely pill-shaped).

## 6. Typography (OD-16b: chosen through style tiles)

| Role | Direction |
|---|---|
| Body (Latin) | A high-quality text face with real italics and tabular numerals (OFL preferred, self-hosted, subset) |
| Display | A characterful display face for mastheads and section headers, the kind of role a 2000s designer's "logo font" played, chosen for legibility |
| Accent | Optional pixel/bitmap face for tiny chrome labels only (A11Y-15) |
| Code | A monospace face |
| Japanese | System Mincho/Gothic for text, and a subset display font for large glyphs (08 §4) |

Japanese typesetting: `line-break: strict`, `word-break: auto-phrase` (progressive), `text-spacing-trim`, `palt` only in headings, and `text-emphasis` for 傍点.

## 7. Assets and artwork policy (ADR-0008)

- **Allowed:** original CSS/SVG interface design, manually designed assets, historical-web-inspired graphical elements made for this site, assets Charles explicitly provides, and commissioned work with recorded rights.
- **Not allowed as visual identity:** generic AI-generated artwork (from the brief).
- **Placeholders:** every non-final asset has `Media.status: 'placeholder'` (or lives under `assets/placeholder/`). In preview it renders with a visible placeholder treatment, and a **production build fails** if any is referenced (CONTENT-12). Placeholders can never quietly become production artwork.
- Every asset records its `origin` and `license` (03 §1). Original artwork is **All Rights Reserved** by default and lives under `assets/` (ADR-0014, 20).
- Photo of Charles: optional (OD-19).
- **88×31 buttons** are truthful: "WCAG 2.2 AA", "No JS required", "Valid HTML", "Built with Astro", "RSS", "llms.txt", "JSON Resume". Every badge claim is backed by an active required merge gate, and a badge is not rendered while its gate is `planned` (16 #11).
- Screenshots of client systems are never allowed for United Airlines (ADR-0006), and are otherwise allowed only with explicit approval.

## 8. Motion

Motion is limited and purposeful: tactile hover and pressed states on chrome, cross-document View Transitions between list and detail pages, gentle masthead details only when no reduced-motion preference is set, and CSS scroll-driven reveal on the timeline (progressive). There is no scroll-jacking and no parallax.

## 9. Design deliverables before component implementation

1. Moodboard in `docs/design/`: annotated references as **links plus written notes** (what is being taken and what is being avoided). Third-party screenshots are **not committed**, because the repository is public and redistributing them isn't allowed (ADR-0014). Local copies for study stay outside the repo.
2. **Style tiles** for Portal, Archive and Dictionary as static HTML prototypes in `docs/design/` (throwaway, not app code). These settle the OD-16b typefaces.
3. Home page and case study mock-ups at 3 breakpoints.
4. Human approval of tiles and mock-ups before building the component library (`ready-for-human` gate).
